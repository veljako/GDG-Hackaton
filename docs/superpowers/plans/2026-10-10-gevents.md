# GEvents Implementation Plan

> For agentic workers: use subagent-driven-development for the independent domain task and review; primary agent implements the tightly coupled UI and integration. User has requested implementation now, so execute continuously.

**Goal:** Deliver a polished local mock app for hackathon organization, profiles and teams.
**Architecture:** Pure typed domain transitions with fictional seed data, React context persisted to localStorage, HashRouter pages, Material Web buttons/dialogs, Motion transitions, local font assets.
**Tech Stack:** React 19, TypeScript, Vite, Material Web, Motion, Phosphor icons, Vitest.

## Global Constraints
- Browser-only mock data; no backend or real OAuth, invitations, emails, algorithm training.
- Brand name GEvents; Google colors and simple geometric team motif.
- Support solo and team applications; organizers control event admission.
- All team members can invite profiles with any admission state.
- Outside invitees remain pending until event approval; accepted members form official teams without a second team approval.
- Preserve history when reusing a team, and request fresh consent from members.
- Responsive at 390px; keyboard access and prefers-reduced-motion.
